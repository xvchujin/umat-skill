# UMAT 更新机制路由：角色隔离与全算子闭包

## I — 方法论骨架（Interpretation）

1. 先按“屈服几何—尺度演化—流动势—强度判据—损伤演化—运动学客观率—数值更新器”给每个公式定角色，不要按文件名或二次型外观归类。
2. 把 J2 与 Hill48 都归入塑性屈服几何，但保留关键差异：J2 的各向同性偏应力几何支持当前径向返回特例；Hill48 的材料轴法向通常不与 J2 试偏应力方向共线。
3. 把标量各向同性硬化 `σy(epbar)` 归入尺度演化；允许它与 J2 或 Hill48 组合，但不要把“硬化各向同性”误读成“屈服几何各向同性”。
4. 把 AFR/non-AFR 归入流动语义：AFR 令屈服函数与塑性势共用函数/参数；non-AFR 分开 `F/G`，并改变流动方向、局部残差、状态和切线。
5. 把 Tsai-Wu `Phi/e` 归入强度起始判据；把方向归因、`dmg` 演化与删除归入后续独立层，禁止让判据自动生成塑性流动或唯一损伤模式。
6. 把客观率与材料轴旋转归入运动学层；它们决定量如何搬运，不替代屈服、硬化、失效或损伤机制。
7. 再辨认三个控制量：`α/ALOUT` 定位显式路径首个屈服交点，`Δλ/dλ` 求塑性一致性修正幅值，`e` 评价强度阈值；为三者保留独立方程、容差和输出。
8. 只在所有依赖算子保持不变且有证明时复用旧更新器；替换屈服函数、塑性势、硬化内变量或运动学后，默认执行依赖闭包审计并重推受影响算子。
9. 若塑性与失效/损伤并存，分别建立支路，再声明耦合顺序、共享状态、切线与事务提交规则。
10. 路由完成后转交专门 skill；不要在本 skill 中凭空补写根搜索、回映、标定或退化律。

### 机制角色判定表

| 用户对象 | 先回答的问题 | 典型输出 | 不得冒充 |
|---|---|---|---|
| J2 / Hill48 | 何时发生塑性屈服、屈服面法向是什么 | 活动集、`∂F/∂σ` | Tsai-Wu 强度或损伤律 |
| `σy(epbar)` / 背应力 | 屈服面如何缩放或平移 | 硬化状态、斜率/背应力 | 屈服几何本身 |
| AFR / non-AFR 的 `G` | 塑性应变沿哪个方向增长 | `∂G/∂σ` | `F` 的同义名 |
| Tsai-Wu `Phi/e` | 组合应力是否到达强度包络 | 起始指数/阈值状态 | 塑性乘子或唯一失效模式 |
| 损伤/删除 | 起始后刚度和存活状态如何演化 | `dmg`、事件、删除状态 | Tsai-Wu 判据必然结论 |
| 客观率/旋转 | 有限转动中如何搬运应力与历史 | 旋转后的张量状态 | 材料更新器 |

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 审查一段 UMAT，发现 `alpha`、`dlambda`、`failure_index` 被放进同一循环或共享同一“残差”。
2. 从材料方程开始设计主流程，不确定应选显式交点、隐式回映还是失效—退化更新。
3. 为同时具有基体塑性与复材失效的模型划分子更新器和状态变量。
4. 解释某个无量纲标量究竟是路径比例、塑性乘子还是强度指标。
5. 把 J2 UMAT 改成 Hill48、把 AFR 改成 non-AFR，或加入背应力/损伤后，判断旧回映与切线还能否复用。

以下同名场景不触发：模型已确认是纯弹性，`alpha` 有热膨胀量纲且只参与热应变扣除，不存在屈服、塑性或损伤分支。

### 语言信号（用户的话里出现这些就应激活）

- “α、Δλ 和 e 到底有什么区别？”
- “这个模型应该走哪个 UMAT update branch？”
- “route material update / choose constitutive integrator”
- “plastic multiplier vs failure index”
- “能不能用返回映射解 Tsai-Wu？”
- “replace von Mises/J2 with Hill48 but keep radial return?”
- “AFR vs non-AFR changes which operators?”
- “yield surface, hardening, damage and objective rate are mixed together.”

### 与相邻 skill 的区分

- 与 `explicit-alpha-yield-intersection` 的区别：本 skill 先判断是否应使用 α；交点 skill 在路由完成后负责物理括区与首根求解。
- 与 `cpa-implicit-return-mapping` 的区别：本 skill 识别 Δλ 的机制角色；CPA skill 负责残差线性化、联合更新和局部收敛。
- 与 `tsai-wu-parameter-audit`/I15“Tsai-Wu 审计/状态机”的区别：本 skill 只把 e 路由到失效支路；兄弟 skill 核对系数、材料轴、方向归因和不可逆退化。
- 与 I02“事务式状态更新”的区别：本 skill 决定调用哪个机制；I02 规定任何机制的候选态、回滚和原子提交。
- 与热膨胀系数的区别：若 `alpha` 只是有量纲的线膨胀系数且模型纯弹性，保留其热学语义，不调用本 skill，也不强行改写成路径交点或塑性乘子。

## E — 可执行步骤（Execution）

当 skill 被激活后，agent 应按以下步骤执行：

1. **为每个待审标量填写机制卡**
   - 至少记录：名称、机制角色、它回答的问题、定义域、材料轴/运动学、输入、方程/判据、输出、会修改的历史量和证据来源。
   - 完成标准：每个对象都落入上表的唯一主角色；同一对象承担多角色时，逐项给出耦合方程，不用“都是控制参数”代替定义。
   - 判停条件：若材料模型、坐标系、运动学或方程缺失，停止路由并请求信息。

2. **按问题类型路由**
   - 路径首次触及屈服面且采用显式分段积分 → `α` 支路。
   - J2 关联塑性且几何/归一化满足径向特例 → J2 径向返回或 CPA 的 `Δλ` 支路。
   - Hill48、non-AFR、随动/混合硬化或其他改变法向/内变量的塑性 → 一般局部回映设计；不得先继承 J2 径向假设。
   - 正交复材组合强度起始判定 → `e` 支路。
   - 刚度折减、删除或客观旋转 → 分别路由到损伤状态机/对象性或表示与运动学审计，不把它们塞入 `Δλ` 方程。
   - 完成标准：每个激活支路都有明确理由；未激活支路也写出排除理由。
   - 判停条件：若模型为纯弹性或没有上述机制，返回“无需这三个控制量”，不要强行选一个。

3. **建立禁混契约**
   - 为屈服函数 `F`、塑性势 `G`、硬化律、强度指数、损伤演化、客观旋转以及 `α/Δλ/e` 分别命名输入、残差、容差和输出。
   - 禁止让 `e` 进入塑性一致性方程，禁止把 `Δλ` 当路径份额，禁止把 `α` 当局部子步长或损伤量；禁止把 Hill48 `F…N`、Tsai-Wu `Fij` 和代码中的同名字母互换。
   - 完成标准：数据流图中不存在未经模型方程支持的跨角色箭头；AFR/non-AFR 的 `F/G` 是否同一必须显式写明。

4. **对模型替换执行全算子依赖闭包**
   - 逐项判定并在需要时重推：活动集、`F` 与 `G`、梯度/Hessian、局部未知量、残差与导数、应力修正、塑性/背应力/硬化状态、耗散、材料轴/Voigt 适配、算法切线、失败事务和验证路径。
   - 只把有独立证明不受替换影响的适配层或工具函数标为可复用；变量名相同、表达式同为二次型或旧代码能运行都不是证明。
   - 完成标准：生成“保留/重推/新增/不适用”四态矩阵；每个“保留”项附对称性、方程或接口不变的证据。
   - 判停条件：若用户只提供新等效应力公式而缺流动势、硬化变量或一致性条件，拒绝给出可直接复用旧回映的结论。

5. **处理真实耦合并做分支级最小核验**
   - 若塑性与失效并存，声明先后次序或联合求解假设、材料坐标变换、共享刚度/强度、切线和失败时的事务边界。
   - α：核对端点、`0≤α≤1` 和首次交点语义；Δλ：核对残差下降及应力/历史量同乘子更新；e：在材料轴下做单轴拉压与纯剪阈值核对。
   - 对 J2→Hill48 替换至少比较试方向、返回后屈服残差、材料轴旋转和切线；对 AFR→non-AFR 至少分别扰动 `F` 与 `G` 参数集。
   - 完成标准：每个控制量只改变声明负责的分支，耦合输出冲突有唯一规则；出现无方程支持的跨机制副作用即回到步骤 1。

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill

- 已经确定算法分支，只需要实现 α 求根、CPA 迭代或 Tsai-Wu 参数审计时；应调用对应兄弟 skill。
- `alpha` 已证为纯弹性热膨胀系数，且模型没有屈服、塑性或损伤机制时；同名不等于屈服交点。
- 纯信息查询、只问某个符号的字面定义、或与 UMAT/材料更新无关的通用软件路由问题。
- 把此 skill 当成耦合本构模型本身；它只做机制分类，不提供未经标定的塑性—损伤耦合律。
- 已经拥有完整 Hill48/非关联局部方程，只需要实现或核验具体返回映射时；转交相应塑性更新技能，不继续停留在路由层。

## 相关 skills

- **depends-on**: 无——本 skill 是机制尚未确定时的入口路由器。
- **contrasts-with**: 无——它不与专用更新器竞争，只负责先分清 `α`、`Δλ` 与 Tsai-Wu `e` 的数学角色。
- **composes-with**: `explicit-alpha-yield-intersection`（显式交点支路）、`cpa-implicit-return-mapping`（隐式塑性支路）、`tsai-wu-parameter-audit`（Tsai-Wu 失效起始支路）。
