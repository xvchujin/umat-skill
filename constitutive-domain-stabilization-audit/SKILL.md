# 物理域守卫与稳定化模型变更审计

## I — 方法论骨架 (Interpretation)

本构公式“算得出来”不等于状态“物理上可接受”。
先把模型的可容许域、奇异面和退化极限写成显式契约，再允许算法评价公式。
域外状态应优先通过拒绝当前试算、缩小局部路径或采用有理论依据的极限式恢复。
分母钳制只能防止浮点崩溃，不能把一个物理奇点变成正确状态。
人工黏聚力、极小刚度或压力平移会改变强度包络和响应，因此必须另命名为模型变体。
稳定化要有触发条件、退出条件、累计触发量和敏感性对照；静默启用会污染验证。
最终报告应把“原模型的预测”和“稳定化模型的结果”分开，而不是用收敛成功掩盖物理变更。

---

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. UMAT 只在低围压、近静水态、屈服尖点或卸载穿越处出现 NaN/Inf。
2. 用户准备通过人工黏聚力、极小刚度、压力平移或分母钳制“帮助收敛”。
3. 同一模型换单位、阈值或稳定化系数后，承载力和局部化结果明显改变。
4. 验证曲线使用原理论解，但实现中打开了改变物理假设的稳定化分支。

### 语言信号 (用户的话里出现这些就应激活)

- “p 接近 0 就发散 / NaN near zero confinement”
- “给一点黏聚力能不能让它收敛 / add artificial cohesion”
- “把刚度乘一个很小的数是否安全 / stiffness scaling”
- “J2 很小时分母怎么保护 / denominator guard”

### 与相邻 skill 的区分

- 与 `umat-failure-cutback-protocol` 的区别：本 skill 判断公式是否进入物理域外及稳定化是否改模；后者处理预算耗尽后的回滚与全局 cutback。
- 与 `explicit-alpha-yield-intersection` 的区别：本 skill 定义可容许域；后者在已定义的路径域内寻找 `α` 交点。
- 与 `umat-hierarchical-validation` 的区别：本 skill 产生稳定化变体及对照要求；后者组织完整验证证据链。

## E — 可执行步骤 (Execution)

1. **登记模型定义域与奇异表达式**
   - 列出压力、应力不变量、内部变量、分母和刚度特征值的合法范围、单位及尺度。
   - 完成标准：每个潜在奇点都有可计算的监测量、容差定义和物理解释。

2. **在公式评价前分类状态**
   - 区分物理可容许、边界极限、数学延拓和非有限状态；同时保存 committed/trial 状态。
   - 完成标准：所有进入深层本构公式的 trial 状态均通过域检查；失败状态没有污染已提交数组。

3. **按恢复层级处理**
   - 优先拒绝并缩小局部路径；其次使用有推导依据的极限式；仍失败则交给 cutback 协议。
   - 判停条件：若没有物理上可辩护的恢复式，不得用任意极小数伪造成功，直接进入失败升级。
   - 完成标准：每个恢复出口都有返回码和可复现实验。

4. **把稳定化声明为模型变体**
   - 写明公式、参数意义、触发/退出条件、不可逆性及累计触发指标，并使用独立名称和开关。
   - 完成标准：关闭稳定化可恢复原模型；日志能回答何时、何处、多少次触发。

5. **做污染与敏感性审计**
   - 在相同加载、网格和参数下比较关闭/开启及至少三档稳定化尺度；参考解必须使用相同物理假设。
   - 完成标准：报告能区分算法稳定性改善和材料响应改变，并说明研究结论是否由稳定化区主导。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 物理域和公式均正常，只是全局增量过大：应先使用失败/cutback 或切线审计。
- 需要有限应变、接触或边界条件层面的稳定化：这些不属于材料点域守卫。
- 试图用固定阈值代替材料参数标定或理论推导。

## 相关 skills

- **depends-on**: 无——它先于任何“为了收敛而加小常数”的实现决策，判断物理域和模型变更。
- **contrasts-with**: `umat-failure-cutback-protocol`——本 skill 处理物理不可容许域、奇异结构和稳定化改模；后者处理可由较小全局增量恢复的失败。
- **composes-with**: 无——本轮只保留它与失败协议之间真正的情境二选一关系，避免把通用审计词汇硬连到所有积分器。
